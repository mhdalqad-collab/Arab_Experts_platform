# شبكة الخبراء العرب — النموذج الموحد للقدرات والخدمات والعروض

**الرمز:** EIM-CSO-001  
**الإصدار:** 1.0  
**الحالة:** خط أساس مفاهيمي للتنفيذ  
**المراجع الملزمة:** EIM-CG-001، EIM-PF-001، EIM-EV-001، EIM-ONT-001  

## 1. الغرض

تحدد هذه الوثيقة كيف تحول الشبكة خبرة العضو المثبتة إلى قدرة قابلة للفهم، ثم
إلى خدمة قابلة للطلب، ثم إلى عرض سوقي قابل للمقارنة، دون الخلط بين هذه
المفاهيم أو تحويل الادعاء التسويقي إلى حقيقة مهنية.

يغطي النموذج الخبراء والمدربين والمستشارين والباحثين والمراكز والفرق، ويدعم
الدراسات والاستشارات والمشاريع والمنتجات والتدريب والتقييم والتدقيق والتحكيم.

## 2. الفصل بين المفاهيم

| المفهوم | التعريف | ما لا يمثله |
|---|---|---|
| القدرة | قابلية مثبتة لتحقيق نتيجة في سياق وشروط محددة | ليست مهارة منفردة أو مسمى وظيفيًا |
| الخدمة | طريقة منظمة لاستخدام قدرة أو مجموعة قدرات لإنتاج نتيجة للعميل | ليست سعرًا أو إعلانًا |
| قالب الخدمة | التعريف المعياري المتكرر للخدمة | ليس عرض مقدم بعينه |
| ملف خدمة مقدم | إعلان مقدم مؤهل أنه يستطيع تقديم قالب خدمة | ليس تعاقدًا |
| العرض السوقي | صيغة منشورة للخدمة تشمل النطاق والنمط والسعر والتوفر | ليس مقترحًا تعاقديًا |
| الطرح | نافذة تنفيذ محددة زمانًا ومكانًا وسعةً؛ تستخدم خصوصًا للتدريب | ليس الدورة الأصلية |
| المقترح | استجابة مخصصة لطلب خدمة محدد | ليس عرضًا عامًا |
| الالتزام التعاقدي | نسخة مقبولة وملزمة من المقترح وفق العقد | لا يتغير بتغيير العرض العام |

**قاعدة حاكمة:** القدرة لا تساوي الخدمة، والخدمة لا تساوي العرض، والعرض لا
يساوي المقترح أو العقد.

## 3. سلسلة التحويل المفاهيمية

1. بصمة مهنية تصف ما مارسه العضو وفي أي سياق ودور.
2. أدلة متحققة تدعم عناصر البصمة ونتائجها.
3. استنتاج قدرة مرشحة مع درجة يقين وحدود صلاحية.
4. اعتماد القدرة أو إبقاؤها كادعاء قيد المراجعة.
5. ربط القدرة بقالب خدمة من CS-CAP.
6. إنشاء ملف خدمة لمقدم محدد.
7. نشر عرض سوقي أو طرح تنفيذي.
8. تخصيص الخدمة ضمن مقترح لاحتياج عميل.
9. تحويل المقترح المقبول إلى التزام تعاقدي ومشروع قابل للتسليم.

لا يجوز القفز من المهارة أو الدورة المكتملة مباشرة إلى خدمة معتمدة دون تحقق
كفاية القدرة المطلوبة.

## 4. نموذج القدرة

### 4.1 هوية القدرة

كل قدرة تسجل بوصفها علاقة بين:

- صاحب القدرة: فرد أو منظمة أو فريق.
- عقدة قدرة معتمدة من CS-CAP.
- النتيجة التي يستطيع تحقيقها.
- السياق والقطاع ونطاق التعقيد.
- مستوى الاستقلال والمسؤولية.
- الدور في التنفيذ.
- درجة اليقين ومصدرها.
- تاريخ آخر ممارسة وفترة الصلاحية.
- القيود والاستثناءات.

### 4.2 مستويات إتقان القدرة

| المستوى | الوصف التشغيلي |
|---|---|
| C1 — بإشراف | ينفذ أجزاء محددة وفق توجيه ومراجعة |
| C2 — مستقل | ينفذ نطاقًا واضحًا باستقلال مهني |
| C3 — يقود | يقود التنفيذ ويتحمل مسؤولية النتيجة |
| C4 — يصمم ويكيف | يصمم المنهج ويكيفه لسياقات معقدة |
| C5 — مرجعي | يضع المعايير ويراجع أعمالًا عالية التعقيد |

المستوى ليس لقبًا اجتماعيًا، ولا يحل محل مستويات البصمة: خبير متمرن، خبير
ممارس، خبير استشاري.

### 4.3 حالة القدرة

`مقترحة → قيد التحقق → مثبتة → نشطة → بحاجة للمراجعة → معلقة → متقاعدة`

يجوز رفض القدرة مع حفظ سبب الرفض. ويعاد التحقق عند تغير جوهري في السياق أو
انقضاء صلاحية الأدلة أو ظهور نزاع مؤثر.

### 4.4 قدرة الفرد والمنظمة والفريق

- قدرة الفرد مشتقة من بصماته وأدلته.
- قدرة المنظمة ليست مجموع قدرات أعضائها تلقائيًا؛ تتطلب عمليات وموارد
  وحوكمة وسجل نتائج مؤسسيًا.
- قدرة الفريق تركيب مؤقت محدد بالمهمة، وتوضح تغطية المتطلبات والتبعيات
  والفجوات وقائد كل نتيجة.
- مغادرة عضو من المنظمة أو الفريق تعيد حساب القدرة المتأثرة ولا تمحو
  السجل التاريخي.

## 5. نموذج قالب الخدمة

قالب الخدمة تعريف معياري مستقل عن مقدم الخدمة، ويتضمن:

| العنصر | الوصف |
|---|---|
| المعرف والرمز | هوية ثابتة وإصدار |
| الاسم العربي والإنجليزي | أسماء العرض المعتمدة |
| نوع الخدمة | بحث وتطوير، استشارة، تنفيذ، تدريب، دراسة، تصميم، إشراف، إدارة مشروع، تدقيق، تحكيم، تقييم |
| المشكلة والنتيجة | ما تعالجه الخدمة وما تنتجه |
| المخرجات القياسية | وثائق، قرار، تصميم، نموذج، تدريب، منتج أو نتيجة |
| القدرات الأساسية | بوابات لا تقبل التعويض |
| القدرات الداعمة | تحسن الجودة ويمكن توزيعها |
| المدخلات المطلوبة | بيانات وقرارات ووصول وتعاون من العميل |
| خطوات التنفيذ | مراحل معيارية قابلة للتخصيص |
| معايير القبول | شروط موضوعية لقبول المخرجات |
| حدود النطاق | ما يشمله القالب وما يستبعده |
| المخاطر والاعتماديات | شروط قد تؤثر في التنفيذ |
| نمط التسليم | حضوري، عن بعد، هجين |
| التصنيفات | روابط CS-PRO وCS-CAP وCS-NEED وCS-CTX |
| الحوكمة | المالك والمراجع والإصدار والحالة |

## 6. ملف خدمة مقدم

ينشئ مقدم مؤهل ملفًا يبين:

- قالب الخدمة وإصداره.
- مقدم الخدمة والعضوية النشطة.
- القدرات التي تغطي المتطلبات.
- الأدلة والنتائج المرجعية المسموح عرضها.
- نطاق القطاعات والدول واللغات.
- الحد الأقصى للتعقيد وحجم المهمة.
- نمط التسليم: حضوري أو عن بعد أو هجين.
- هل يقدمها منفردًا أم عبر منظمة أو فريق؟
- الأدوار التي يستطيع تحملها.
- الاستثناءات وتعارض المصالح المحتمل.
- تاريخ التحقق وموعد المراجعة.

لا ينشر الملف إذا كانت قدرة أساسية مفقودة، أو العضوية معلقة، أو درجة اليقين
أقل من الحد الذي يحدده قالب الخدمة.

## 7. العرض السوقي

العرض نسخة قابلة للاكتشاف والمقارنة من ملف الخدمة، ويحتوي على:

- عنوان واضح وملخص النتيجة.
- الجمهور أو نوع العميل المناسب.
- النطاق والباقات والخيارات.
- المخرجات والمدة التقديرية.
- نمط ومكان التنفيذ.
- التوفر من وإلى.
- سعر الساعة بالدولار وسعر يوم العمل بالدولار كل على حدة، أو سعر ثابت/نطاق
  سعري عند ملاءمته.
- الضرائب والمصروفات وما إذا كانت ضمن السعر.
- اللغات.
- مستوى الخدمة وأزمنة الاستجابة.
- شروط الإلغاء وإعادة الجدولة.
- روابط ملف المقدم والأدلة العامة.
- تاريخ النفاذ والإصدار.

السعر المنشور مؤشر سوقي لا يصبح ملزمًا إلا داخل مقترح مقبول.

## 8. أنواع العروض

| النوع | الاستخدام |
|---|---|
| عرض قياسي | خدمة متكررة بنطاق وسعر معروفين |
| عرض قابل للتهيئة | خيارات وباقات ضمن حدود معتمدة |
| طلب عرض سعر | لا يسعر إلا بعد فهم الاحتياج |
| اشتراك خدمة | منفعة متكررة وحدود استخدام وفترة تجديد |
| طرح تدريبي | تاريخ ومكان ومدرب وسعة وسعر تسجيل |
| عرض فريق | قدرات متكاملة وأدوار ومسؤولية قيادة |
| عرض مؤسسي | مقدم باسم منظمة وموارد وضمانات مؤسسية |

## 9. الفرق بين الدورة والطرح التدريبي

- **الدورة:** أصل معرفي/تدريبي له مالك محتوى وإصدار ومخرجات تعلم وتصنيف.
- **الطرح:** تنفيذ محدد للدورة بمدرب أو أكثر، مركز، لغة، تاريخ، نمط، سعة وسعر.
- يمكن للدورة الواحدة أن تمتلك طروحات متعددة.
- يمكن أن ينسب الطرح إلى مركز ومدرب معًا، مع بيان دور كل طرف.
- تغيير التاريخ أو المكان ينشئ طرحًا جديدًا أو تعديلًا محكومًا، ولا يكرر
  الدورة.
- تغيير جوهري في المحتوى أو المخرجات ينشئ إصدار دورة جديدًا.

## 10. تكوين الفرق

يتكون عرض الفريق من:

- قائد مسؤول عن النتيجة الإجمالية.
- أعضاء بأدوار ومسؤوليات معلنة.
- مصفوفة تغطية القدرات.
- قدرة احتياطية للمتطلبات الحرجة عند الحاجة.
- قواعد توزيع العمل والتسليم والمراجعة.
- تضارب المصالح والتوفر المتزامن.
- حصة كل عضو في الإنجاز، تحفظ لاحقًا في بصمته.

لا يسمح بتكرار قدرة العضوين على أنها تغطيتان مستقلتان إذا كانت الأدلة تعود إلى
المشروع أو المصدر نفسه دون تمييز مساهمة كل منهما.

## 11. الربط باحتياج العميل

يرتبط قالب الخدمة بعقد CS-NEED بواسطة `MAP-ADDRESSES`، وتحدد المطابقة:

1. النتيجة المطلوبة.
2. نطاق المشكلة وسياقها.
3. القدرات الأساسية.
4. القيود والبوابات غير القابلة للتعويض.
5. المخرجات ومعايير القبول.
6. النمط والموقع واللغة.
7. الوقت والميزانية.
8. المخاطر والسرية.

إذا كان الاحتياج غير مكتمل، تعرض المنصة أسئلة استيضاح ولا تفترض خدمة واحدة.
ويظل العميل صاحب القرار بعد رؤية البدائل والتفسير والمقارنة.

## 12. الربط بالمطابقة

تستخدم المطابقة طبقات منفصلة:

- **الأهلية:** العضوية، الصلاحية، المتطلبات القانونية، عدم التعارض.
- **بوابات القدرة:** القدرات الأساسية والحد الأدنى للمستوى واليقين.
- **الملاءمة:** السياق والقطاع والتعقيد والحداثة.
- **القابلية التشغيلية:** التوفر والنمط واللغة والدولة.
- **التجارية:** السعر والمدة وشروط العرض.
- **الجودة:** النتائج والسمعة والشكاوى المصانة.

لا يعوض السعر المنخفض قدرة أساسية مفقودة. ولا ترفع العضوية الذهبية ترتيب
الملاءمة المهنية. ويفصل النظام بوضوح بين النتائج الممولة والترتيب الموضوعي.

## 13. قابلية المقارنة

تعرض المقارنة حقولًا موحدة:

- نسبة التطابق وسببها.
- النتيجة والنطاق.
- مقدم الخدمة ونوعه.
- القدرات الأساسية وتغطيتها.
- درجة اليقين وحداثة الأدلة.
- الخبرات السياقية.
- المدة والتوفر.
- نمط التنفيذ واللغة والدولة.
- السعر الكلي والتكاليف المستبعدة.
- التقييم المحكوم وعدد الحالات.
- المخاطر والاستثناءات.

تظهر القيم غير المتاحة بوصفها «غير معلنة» أو «غير متحققة»، ولا تحول إلى صفر.

## 14. منع الازدواجية

### 14.1 بصمة قالب الخدمة

`نوع النتيجة + عقدة المشكلة + الممارسة + القدرة الأساسية + السياق + المخرج`

### 14.2 بصمة ملف المقدم

`قالب الخدمة + المقدم + نطاق السياق + مستوى القدرة + نمط التسليم`

### 14.3 بصمة العرض

`ملف المقدم + الباقة + نطاق السعر + فترة النفاذ + السوق/الدولة`

عند الاشتباه تعرض المنصة السجلات المشابهة وخيارات: استخدام القائم، إصدار
جديد، باقة جديدة، ترجمة، طرح، أو طلب دمج. ولا تمنع السجل اعتمادًا على الاسم
وحده.

## 15. الإصدارات والتغييرات

1. تعديل إملائي أو توضيحي ينشئ مراجعة طفيفة.
2. تغيير النتيجة أو القدرات الأساسية أو معايير القبول ينشئ إصدارًا رئيسيًا.
3. العرض الجديد لا يغير المقترحات أو العقود السابقة.
4. يحتفظ كل مقترح بنسخة ثابتة من القالب وملف المقدم والعرض المستخدم.
5. إيقاف قالب يمنع إنشاء عروض جديدة ولا يمحو التاريخ.
6. عند استبدال قالب، يحدد مسار ترحيل للعروض النشطة.

## 16. دورات الحياة

### 16.1 قالب الخدمة

`مقترح → مسودة → مراجعة تخصصية → معتمد → نشط → بحاجة للمراجعة → متقاعد/مستبدل`

### 16.2 ملف خدمة مقدم

`مسودة → فحص اكتمال → تحقق قدرة → معتمد → منشور → معلق → منتهي/مسحوب`

### 16.3 العرض

`مسودة → معاينة → منشور → موقوف مؤقتًا → منتهي → مؤرشف`

لا يجوز حذف سجل استخدم في طلب أو مقارنة أو مقترح أو عقد؛ يؤرشف مع الاحتفاظ
بمرجعيته.

## 17. الصلاحيات

| الفاعل | الصلاحيات الرئيسية |
|---|---|
| مقدم الخدمة | إعداد ملفه وعروضه ضمن القوالب والقدرات المعتمدة |
| مالك المنظمة | اعتماد عروض المنظمة وتعيين ممثليها |
| قائد الفريق | اقتراح الفريق وتوزيع القدرات، دون اعتماد قدرة العضو |
| مالك المجال | إدارة قالب الخدمة والتصنيف والمتطلبات |
| محقق مهني | التحقق من القدرة والأدلة، دون تسعير العرض |
| مراجع جودة | اعتماد معايير القبول ومراجعة الأداء |
| مدير المنصة | إدارة الحالات والاستثناءات وفق فصل الواجبات |
| العميل | إنشاء الاحتياج والمقارنة والاختيار، دون تعديل بيانات المقدم |

من أنشأ قالبًا أو قدرة لا يعتمدها منفردًا عندما تكون الخدمة عالية المخاطر.

## 18. الخصوصية والملكية الفكرية

- تفصل بيانات العرض العامة عن الأدلة الخاصة.
- تعرض الأدلة وفق صلاحياتها وعلى أقل قدر لازم.
- يحدد مالك المحتوى، المؤلف، حقوق الاستخدام، الحصرية، السماح لأكثر من مدرب،
  مستوى السرية، شروط المواد، ورابط النسخة المعتمدة.
- لا تنسخ مواد دورة أو منهجية داخل عرض مقدم آخر لمجرد ارتباطها الدلالي.
- يحجب تعارض المصالح قبل كشف بيانات العميل الحساسة.
- تسجل كل مشاهدة أو مشاركة لوثيقة مقيدة في سجل التدقيق.

## 19. مؤشرات الجودة

تقاس الخدمة بعد التنفيذ من خلال:

- قبول المخرجات من أول مرة.
- الالتزام بالوقت والنطاق.
- معدل التغييرات وأسبابها.
- تحقق النتيجة المتفق عليها.
- جودة التواصل والتوثيق.
- الشكاوى والنزاعات والنتيجة.
- قابلية إعادة الاستخدام أو الاستدامة.

لا يجمع تقييم التدريب والاستشارة والتدقيق في متوسط واحد؛ لكل نوع مؤشرات
وسياق، ثم تحسب سمعة مركبة قابلة للتفسير.

- **CSO-BR-001:** لا تعتمد قدرة دون ربطها ببصمة وأدلة وسياق.
- **CSO-BR-002:** لا تكفي شهادة حضور لإثبات قدرة تنفيذ مستقلة.
- **CSO-BR-003:** قدرة المنظمة لا تستنتج آليًا من مجموع أعضاء حاليين.
- **CSO-BR-004:** كل قالب خدمة يرتبط بنتيجة ومخرج واحد على الأقل.
- **CSO-BR-005:** كل قالب يحدد القدرات الأساسية غير القابلة للتعويض.
- **CSO-BR-006:** لا ينشر ملف مقدم عند غياب قدرة أساسية.
- **CSO-BR-007:** لا يعرض مقدم خدمة بعضوية غير نشطة.
- **CSO-BR-008:** لا يرفع الاشتراك المدفوع ملاءمة المطابقة المهنية.
- **CSO-BR-009:** السعر العام غير ملزم قبل قبوله في مقترح.
- **CSO-BR-010:** تحفظ العملة والوحدة والفترة لكل سعر.
- **CSO-BR-011:** سعر الساعة وسعر يوم العمل حقلاّن مستقلان.
- **CSO-BR-012:** التوفر فترة زمنية وليس وصف حالة حرًا.
- **CSO-BR-013:** نمط التسليم قيمة محكومة: حضوري، عن بعد، هجين.
- **CSO-BR-014:** الدورة كيان مستقل عن الطرح التدريبي.
- **CSO-BR-015:** كل طرح يرتبط بإصدار دورة واحد.
- **CSO-BR-016:** المدرب المرتبط بالطرح عضو مسجل ونشط، وإلا يبقى الحقل فارغًا.
- **CSO-BR-017:** لا ينشئ تشابه الاسم وحده دورة أو خدمة مكررة.
- **CSO-BR-018:** التغيير الجوهري ينتج إصدارًا ولا يكتب فوق التاريخ.
- **CSO-BR-019:** المقترح المقبول يحتفظ بلقطة ثابتة من العرض.
- **CSO-BR-020:** العقد لا يتغير بتعديل العرض السوقي اللاحق.
- **CSO-BR-021:** لا يعوض عامل تجاري بوابة قدرة أساسية.
- **CSO-BR-022:** نتيجة المطابقة تفسر القدرات والروابط والفجوات.
- **CSO-BR-023:** الفريق يحدد قائدًا ومسؤولًا لكل مخرج.
- **CSO-BR-024:** مساهمة كل عضو تحفظ مستقلة ولا تنسب له نتيجة الفريق كاملة.
- **CSO-BR-025:** لا تعرض الأدلة المقيدة داخل العرض العام.
- **CSO-BR-026:** ملكية المحتوى وحق استخدامه شرطان سابقان للنشر.
- **CSO-BR-027:** القيم غير المعلنة لا تعامل على أنها صفر.
- **CSO-BR-028:** لا يحذف كيان استُخدم في معاملة؛ يؤرشف.
- **CSO-BR-029:** يعتمد القالب عالي المخاطر بمراجعة مستقلة.
- **CSO-BR-030:** كل استثناء تشغيلي له مبرر وصلاحية وسجل تدقيق.

## 22. معايير القبول المفاهيمية

تعد الحزمة مكتملة عندما يستطيع النموذج:

1. التمييز برمجيًا بين القدرة والخدمة والعرض والمقترح والعقد.
2. تمثيل قدرة الفرد والمنظمة والفريق دون تضخيم.
3. منع نشر خدمة لا تغطي بوابات قدراتها الأساسية.
4. ربط الخدمة بالتصنيف المهني والتدريبي والاحتياج والسياق.
5. إدارة دورة منفصلة عن إصداراتها وطروحاتها.
6. مقارنة عروض مختلفة ضمن حقول قابلة للفرز والتفسير.
7. اكتشاف التشابه والازدواجية مع مسار قرار لا يعتمد على الاسم وحده.
8. حفظ الإصدارات واللقطات المستخدمة في المعاملات السابقة.
9. حماية الأدلة والملكية الفكرية وفق مستوى الإفصاح.
10. تفسير نتائج البحث والمطابقة وتكوين الفريق.
11. تطبيق فصل الواجبات في الاعتماد.
12. استخراج كيانات منطقية قابلة للتحويل إلى قاموس بيانات وDDL.

## 23. القرارات المؤجلة للحزمة التالية

تترك التفاصيل التالية لحزمة **احتياج العميل وبصمة المهمة**:

- البنية الكاملة للمشكلة والنتيجة والقيود.
- بوابات اكتمال الاحتياج حسب الدراسة والاستشارة والمشروع والمنتج.
- إدارة البدائل والأولويات والأوزان التي يحددها العميل.
- تحويل الاحتياج إلى طلب خدمة وإصداراته.
- قواعد الإفصاح التدريجي لمقدمي الخدمة.
