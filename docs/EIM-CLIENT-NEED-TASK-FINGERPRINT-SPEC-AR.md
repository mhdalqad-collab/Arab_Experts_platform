# شبكة الخبراء العرب — مواصفة احتياج العميل وبصمة المهمة

**الرمز:** EIM-NTF-001  
**الإصدار:** 1.0  
**الحالة:** خط أساس مفاهيمي للتنفيذ  
**المراجع الملزمة:** EIM-CG-001، EIM-PF-001، EIM-EV-001، EIM-ONT-001، EIM-CSO-001  

## 1. الغرض

تحدد هذه الوثيقة الطريقة المؤسسية لتحويل حاجة العميل، التي قد تبدأ بوصف غير
منظم لمشكلة أو فرصة، إلى **بصمة مهمة قابلة للفهم والمقارنة والمطابقة
والتعاقد**، مع بقاء العميل صاحب القرار النهائي.

تغطي البصمة احتياجات من نوع:

- دراسة أو بحث تطبيقي.
- استشارة متخصصة.
- مشروع أو دعم مشروع.
- تطوير منتج أو منهجية أو نموذج.
- تدريب أو ورشة عمل.
- تقييم أو مراجعة أو تدقيق أو تحكيم.
- خبير أو فريق مؤقت.

## 2. الحدود المفاهيمية

| المفهوم | التعريف | الحد الفاصل |
|---|---|---|
| الاحتياج | مشكلة أو فرصة أو نتيجة يرغب العميل في معالجتها | ليس طلب خدمة منشورًا |
| بصمة الاحتياج | تمثيل منظم للحالة والنتيجة والقيود والأولوية | لا تتضمن حلًا مفروضًا |
| بصمة المهمة | مواصفات العمل المطلوب والقدرات والمخرجات والقبول | ليست مقدمًا أو عرضًا |
| طلب الخدمة | نسخة منشورة ومحكومة من بصمة المهمة لدعوة مقدمي الخدمة | لا يساوي الاحتياج الأصلي |
| طلب الاستيضاح | سؤال منظم لإكمال معلومة مؤثرة | لا يعد عرضًا |
| الاستجابة | إفادة أولية من مقدم الخدمة | لا تعد مقترحًا ملزمًا |
| المقترح | حل ونطاق وسعر وجدول مخصص للطلب | يصبح ملزمًا فقط بعد القبول والتعاقد |

**قاعدة حاكمة:** الاحتياج ليس طلب خدمة، وبصمة المهمة ليست حلًا مسبقًا، ونتيجة
المطابقة ليست قرار العميل.

## 3. سلسلة التحويل

1. يسجل العميل المشكلة أو الفرصة بلغته.
2. تحفظ صياغته الأصلية دون استبدال.
3. تستخرج المنصة عناصر أولية وتقترح أسئلة استيضاح.
4. يعتمد العميل بصمة الاحتياج.
5. تولد بصمة مهمة واحدة أو عدة بدائل ممكنة.
6. يختار العميل البديل المراد نشره.
7. ينشأ طلب خدمة بإصدار ثابت ومستوى إفصاح محدد.
8. تنفذ المطابقة وتعرض خيارات قابلة للتفسير والمقارنة.
9. يضع العميل قائمة مختصرة ويطلب استجابات أو مقترحات.
10. يحفظ القرار وأسبابه، ثم تبدأ دورة المقترح والعقد.

لا يغير الذكاء الاصطناعي النص الأصلي أو ينشر طلبًا نيابة عن العميل دون
موافقته الصريحة.

## 4. هوية الاحتياج

يتضمن سجل الاحتياج:

- معرفًا دائمًا.
- العميل المالك: فرد أو منظمة.
- الوحدة التنظيمية أو المشروع المعني.
- عنوانًا مختصرًا.
- الوصف الأصلي للمشكلة أو الفرصة.
- سبب ظهور الاحتياج.
- النتيجة أو الأثر المرغوب.
- الفئة: دراسة، استشارة، مشروع، منتج، تدريب، تقييم، فريق.
- أصحاب المصلحة.
- حالة الاحتياج وإصداره.
- درجة السرية ومالك القرار.
- المصدر وتاريخ الإنشاء وآخر تحديث.

يجوز للعميل امتلاك عدة احتياجات مرتبطة ببرنامج أو مبادرة واحدة، لكن لا تدمج
تلقائيًا لمجرد تشابه العنوان.

## 5. بنية بصمة الاحتياج

تتكون البصمة من تسعة محاور مستقلة:

| المحور | المحتوى |
|---|---|
| N1 — الحالة الراهنة | السياق والأعراض والبيانات المتاحة |
| N2 — المشكلة/الفرصة | ما يحتاج معالجة ولماذا |
| N3 — النتيجة المرغوبة | التغيير أو القيمة المتوقع تحقيقها |
| N4 — المستفيدون | المتأثرون والمستخدمون وصاحب القبول |
| N5 — النطاق | الداخل والخارج والحدود الجغرافية والتنظيمية |
| N6 — القيود | الوقت والميزانية واللغة والموقع والتقنية والتنظيم |
| N7 — المخاطر | الحساسية وعدم اليقين والتبعيات |
| N8 — الأولوية | الأهمية والاستعجال وأثر التأخير |
| N9 — النجاح | مؤشرات النتيجة وطريقة التحقق |

لكل محور حالة: غير مدخل، أولي، مكتمل، مؤكد، أو بحاجة للمراجعة.

## 6. بصمة المهمة

تحول بصمة الاحتياج إلى مواصفة تنفيذية تتضمن:

- نوع المهمة والمسار المقترح.
- النتيجة الرئيسية والنتائج الفرعية.
- المخرجات المطلوبة.
- معايير قبول كل مخرج.
- الأنشطة أو المراحل المتوقعة دون فرض منهج مقدم الخدمة.
- القدرات الأساسية والداعمة.
- مستوى القدرة واليقين الأدنى.
- مستوى التعقيد والاستقلال والمسؤولية.
- خبرة القطاع والسياق المطلوبة.
- شكل الفريق والأدوار الحرجة.
- المدخلات التي يوفرها العميل.
- التبعيات والافتراضات.
- مدة التنفيذ والموعد المستهدف.
- مكان ونمط التنفيذ: حضوري، عن بعد، هجين.
- اللغات والدول.
- الميزانية أو النطاق المالي بالدولار عند طلب العميل.
- السرية والملكية الفكرية ومتطلبات البيانات.
- طريقة التقييم وأوزان المعايير.

## 7. التخصص والسياق

ترتبط المهمة بعقد معتمدة من:

- `CS-NEED` للمشكلة والنتيجة.
- `CS-PRO` للمجال والاختصاص والممارسة والمحتوى التفصيلي.
- `CS-CAP` للقدرات والخدمات.
- `CS-CTX` للقطاع والدولة والبيئة والتعقيد.
- `CS-TRN` عندما يكون التدريب حلًا محتملًا.

تختار القوائم المترابطة المسار من المجال الرئيسي إلى الاختصاص الرئيسي ثم
الاختصاص الفرعي ثم نوع الأعمال والممارسات ثم المحتوى التفصيلي. ويسمح بأكثر من
مسار مع تحديد مسار أساسي ومسارات مساندة.

## 8. أنواع المهمة وبوابات الاكتمال

### 8.1 دراسة أو بحث تطبيقي

لا ينشر الطلب قبل تحديد سؤال الدراسة، نطاقها، مصادر البيانات، المنهج المتوقع
أو قيوده، المخرجات، جمهور التقرير، ومعيار قبول النتائج.

### 8.2 استشارة متخصصة

يلزم تحديد القرار المطلوب دعمه، المشكلة، أصحاب القرار، البيانات المتاحة،
شكل التوصية، والحد الفاصل بين المشورة والتنفيذ.

### 8.3 مشروع أو دعم مشروع

يلزم تحديد الهدف، المرحلة الحالية، النطاق، المخرجات، الجدول، الحوكمة،
الاعتماديات، وحدود مسؤولية الخبير أو الفريق.

### 8.4 تطوير منتج أو نموذج

يلزم تحديد المستخدم، المشكلة، متطلبات المنتج، مستوى النضج الحالي، حقوق
الملكية، معايير الأداء، النموذج الأولي، والاختبارات المطلوبة.

### 8.5 تدريب أو ورشة

يلزم تحديد الفئة المستهدفة، الفجوة، مخرجات التعلم، المستوى، العدد، اللغة،
النمط، المدة، التقييم، وهل المطلوب دورة قائمة أم تصميم محتوى جديد.

### 8.6 تقييم أو تدقيق أو تحكيم

يلزم تحديد موضوع التقييم، المعيار المرجعي، الاستقلال المطلوب، نطاق الأدلة،
شكل التقرير، صلاحية الوصول، وتضارب المصالح.

### 8.7 خبير أو فريق مؤقت

يلزم تحديد الأدوار، القدرات، مستوى المسؤولية، مدة المشاركة، آلية الإدارة،
المخرجات، وتوزيع المساءلة.

## 9. المخرجات ومعايير القبول

كل مخرج يسجل منفصلًا ويحتوي على:

- الاسم والوصف والنوع.
- المسؤول عن القبول.
- الصيغة واللغة.
- تاريخ الاستحقاق.
- معايير القبول القابلة للتحقق.
- الأدلة المطلوبة لإثبات الإنجاز.
- التبعيات.
- السرية والملكية.
- هل هو إلزامي أم اختياري؟
- وزن المخرج في قبول المهمة.

لا تستخدم عبارات مثل «جودة عالية» وحدها معيارًا للقبول؛ يجب تحويلها إلى شرط
قابل للفحص أو مراجعة مهنية محددة.

## 10. القيود والبوابات

تنقسم الشروط إلى:

- **بوابات إلزامية:** غيابها يستبعد الخيار، مثل ترخيص أو لغة أو دولة أو قدرة
  أساسية.
- **معايير موزونة:** تؤثر في الترتيب، مثل السعر والخبرة السياقية والمدة.
- **تفضيلات:** تحسن الملاءمة ولا تستبعد.
- **معلومات:** تعرض للمقارنة فقط.

لا يجوز تحويل معيار موزون إلى بوابة أو العكس دون موافقة العميل وتسجيل
التعديل.

## 11. أوزان المطابقة

يحدد العميل الأوزان ضمن مجموع 100%، وفق نموذج افتراضي قابل للتعديل:

| المعيار | الوزن الافتراضي |
|---|---:|
| القدرات والممارسات | 30% |
| الأدلة ودرجة اليقين | 20% |
| خبرة القطاع والسياق | 15% |
| المخرجات والمنهج | 10% |
| التوفر والمدة | 10% |
| السعر والقيمة | 10% |
| السمعة والجودة | 5% |

قواعد الأوزان:

1. تعاد الأوزان إلى 100% قبل التشغيل.
2. تعرض أثر كل وزن على النتيجة.
3. تحفظ نسخة الأوزان مع تشغيل المطابقة.
4. لا تؤثر الأوزان في بوابات الأهلية.
5. يتيح النظام سيناريوهات متعددة للمقارنة، مثل الجودة أولًا أو السرعة أولًا.
6. لا يغير النظام أوزان العميل سرًا لتحسين نتائج مدفوعة.

## 12. الميزانية والوقت

- الميزانية رقم أو نطاق رقمي، ويظهر رمز الدولار.
- يجوز إخفاؤها عن مقدمي الخدمة مع استخدامها داخليًا في المطابقة.
- توضح الضرائب والمصروفات والسفر وما إذا كانت مشمولة.
- المدة رقم بالأيام عند المهمة، مع تاريخ بداية ونهاية عند ثبوتهما.
- يميز النظام بين الموعد المرغوب والموعد الإلزامي.
- أثر التأخير يسجل كقيمة أو خطر، لا كعبارة عامة فقط.

## 13. الإفصاح التدريجي والخصوصية

تحدد كل معلومة بمستوى:

| المستوى | من يراها |
|---|---|
| P0 — خاص | مالك الاحتياج والمخولون داخل العميل |
| P1 — إدارة المنصة | موظفون مخولون للحاجة التشغيلية |
| P2 — مرشح مؤهل | مقدم اجتاز البوابات وقبل شروط السرية |
| P3 — قائمة مختصرة | مقدم اختاره العميل للقائمة المختصرة |
| P4 — طرف متعاقد | مقدم بعد القبول أو التوقيع |
| P5 — عام | معلومات يسمح العميل بنشرها |

تسبق اتفاقية السرية كشف البيانات الحساسة عند اشتراطها. ويعرض ملف مقدم الخدمة
من البيانات ما يلزم فقط لاتخاذ القرار.

## 14. عدم اليقين والافتراضات

يسجل لكل عنصر مهم:

- هل هو حقيقة، تقدير، افتراض، أو غير معروف؟
- مصدر المعلومة.
- درجة الثقة.
- أثر الخطأ.
- من يتحقق منه ومتى؟

لا يعاقب العميل في المطابقة على بيانات لم يستطع معرفتها؛ بل تظهر فجوة
معلومات ويخفض يقين النتيجة أو يطلب استيضاح.

## 15. إصدار الاحتياج والطلب

1. يحفظ النص الأصلي والبصمة المنظمة في كيانين مرتبطين.
2. كل تعديل مؤثر ينشئ إصدارًا جديدًا.
3. الإصدار المنشور لا يعدل بأثر رجعي.
4. تشغيل المطابقة يرتبط بإصدار واحد محدد.
5. الردود والمقترحات تبقى مرتبطة بالإصدار الذي استجابت له.
6. تغيير بوابة أو مخرج أو ميزانية أو موعد جوهري يتطلب إصدارًا جديدًا وإشعار
   الأطراف.
7. يجوز سحب إصدار مع حفظ سبب السحب وتاريخه.

## 16. دورة الحياة

### 16.1 الاحتياج

`فكرة → مسودة → استيضاح → مكتمل → معتمد داخليًا → محول إلى مهمة → مغلق/ملغى`

### 16.2 بصمة المهمة

`مولدة → قيد المراجعة → معتمدة → منشورة ضمن طلب → مستبدلة/مؤرشفة`

### 16.3 طلب الخدمة

`مسودة → فحص اكتمال → معتمد → منشور → استقبال استجابات → قائمة مختصرة → تفاوض → ممنوح → مغلق/ملغى`

لا يسمح بالانتقال إلى «منشور» إذا فشلت بوابات اكتمال نوع المهمة أو إعدادات
السرية أو صلاحية الناشر.

## 17. الاستيضاح

- يجمع النظام الأسئلة المتشابهة لتقليل الإزعاج.
- يميز سؤال المنصة عن سؤال مقدم الخدمة.
- يمنع سؤالًا يكشف هوية مقدم منافس أو بيانات غير لازمة.
- ترتبط الإجابة بإصدار الطلب.
- إذا غيرت الإجابة النطاق أو البوابات، ينشأ إصدار جديد.
- توزع الإجابة المسموح بها بالتساوي على المؤهلين لمنع عدم تكافؤ المعلومات.

## 18. البحث والمطابقة والقائمة المختصرة

تعرض النتيجة:

- درجة التطابق الإجمالية.
- تحقق البوابات.
- درجة كل معيار ووزنه.
- مسار التصنيف الدلالي.
- القدرات المغطاة والفجوات.
- الأدلة ودرجة اليقين دون كشف المحمي.
- السعر والوقت والتوفر.
- المخاطر والاستثناءات.
- سبب الاستبعاد إن سمحت السياسة.

يجوز للعميل:

- تغيير الأوزان وتشغيل سيناريو جديد.
- تثبيت خيار للمقارنة.
- إضافة خيار إلى القائمة المختصرة.
- طلب استيضاح.
- استبعاد خيار مع سبب اختياري.
- اختيار مقدم أو فريق.

ولا يجوز للنظام إعلان «الأفضل مطلقًا»؛ بل «الأعلى وفق الإصدار والأوزان
والبيانات المتاحة».

## 19. تشكيل فريق للمهمة

عندما لا يغطي مقدم واحد البوابات:

1. تحلل القدرات إلى حزم.
2. تقترح أدوارًا وقائدًا.
3. تبحث عن أعضاء مكملين.
4. تتحقق من التوفر والتعارض واللغة والمكان.
5. تحسب تغطية الفريق دون عد مزدوج.
6. تعرض الفجوات والتبعيات.
7. يعتمد العميل التشكيل قبل دعوة الأعضاء.

لا تكشف أسماء العميل أو بياناته الخاصة للأعضاء المقترحين قبل مستوى الإفصاح
المناسب.

## 22. قواعد الأعمال المؤسسية

- **NTF-BR-001:** يحفظ وصف العميل الأصلي دون استبدال.
- **NTF-BR-002:** لا تنشر صياغة آلية قبل اعتماد العميل.
- **NTF-BR-003:** الاحتياج مستقل عن طلب الخدمة.
- **NTF-BR-004:** بصمة المهمة مستقلة عن مقدم الخدمة.
- **NTF-BR-005:** كل مهمة ترتبط بنتيجة قابلة للوصف.
- **NTF-BR-006:** كل مخرج إلزامي له معيار قبول ومسؤول قبول.
- **NTF-BR-007:** لا تستخدم صفة عامة وحدها معيار قبول.
- **NTF-BR-008:** لكل نوع مهمة بوابات اكتمال خاصة.
- **NTF-BR-009:** لا ينشر الطلب قبل اجتياز بوابات نوعه.
- **NTF-BR-010:** البوابة المفقودة لا تعوض بالوزن.
- **NTF-BR-011:** مجموع أوزان المطابقة يساوي 100%.
- **NTF-BR-012:** تحفظ الأوزان مع كل تشغيل مطابقة.
- **NTF-BR-013:** لا تغير المنصة أوزان العميل دون موافقته.
- **NTF-BR-014:** التمويل لا يرفع الترتيب الموضوعي.
- **NTF-BR-015:** الميزانية قيمة أو نطاق رقمي مع عملة محددة.
- **NTF-BR-016:** المدة في المهمة رقم بالأيام.
- **NTF-BR-017:** الموعد المرغوب لا يعامل كموعد إلزامي.
- **NTF-BR-018:** لكل معلومة حساسة مستوى إفصاح.
- **NTF-BR-019:** لا يكشف مستوى أعلى قبل تحقق شرطه.
- **NTF-BR-020:** عدم المعرفة يظهر كفجوة ولا يحول إلى صفر.
- **NTF-BR-021:** كل افتراض مؤثر له مالك تحقق وموعد.
- **NTF-BR-022:** التعديل الجوهري ينشئ إصدارًا جديدًا.
- **NTF-BR-023:** لا تعدل نسخة منشورة بأثر رجعي.
- **NTF-BR-024:** الرد والمقترح يرتبطان بإصدار الطلب المستهدف.
- **NTF-BR-025:** الاستيضاح المؤثر في النطاق ينتج إصدارًا جديدًا.
- **NTF-BR-026:** توزع الإجابات المشتركة بعدالة على المؤهلين.
- **NTF-BR-027:** قرار المطابقة توصية تفسيرية وليس قرارًا آليًا.
- **NTF-BR-028:** العميل صاحب قرار القائمة المختصرة والاختيار.
- **NTF-BR-029:** لا يعلن خيار «الأفضل مطلقًا».
- **NTF-BR-030:** تكوين الفريق يمنع العد المزدوج للقدرات.
- **NTF-BR-031:** كل فريق مقترح يحدد قائدًا ومسؤولية المخرجات.
- **NTF-BR-032:** لا يكشف تضارب المصالح بعد كشف البيانات الحساسة؛ يفحص قبله.
- **NTF-BR-033:** يسجل سبب الاستبعاد الآلي أو الإداري.
- **NTF-BR-034:** لا يحذف طلب استقبل استجابة؛ يغلق أو يؤرشف.
- **NTF-BR-035:** كل استثناء له صاحب صلاحية ومبرر ومدة وسجل تدقيق.

## 23. معايير القبول المفاهيمية

تعد الحزمة مكتملة عندما يستطيع النموذج:

1. فصل الاحتياج وبصمته وبصمة المهمة وطلب الخدمة.
2. تمثيل الأنواع السبعة مع بوابات اكتمال مستقلة.
3. حفظ صياغة العميل الأصلية والاقتراحات والتحويلات.
4. تمثيل المخرجات ومعايير القبول والمسؤولين.
5. التمييز بين البوابات والمعايير والتفضيلات والمعلومات.
6. إدارة الأوزان والسيناريوهات دون التأثير في الأهلية.
7. تطبيق الإفصاح التدريجي على مستوى كل معلومة.
8. إدارة عدم اليقين والافتراضات وفجوات البيانات.
9. إصدار الطلب وربط كل نتيجة ورد ومقترح بالإصدار الصحيح.
10. تفسير المطابقة والقائمة المختصرة وقرار العميل.
11. اقتراح فريق مكمل مع كشف الفجوات ومنع العد المزدوج.
12. تحويل الكيانات إلى نموذج منطقي وقاموس بيانات وصلاحيات.

## 24. القرارات المؤجلة للحزمة التالية

تنتقل التفاصيل التالية إلى حزمة **المطابقة والتوصية وتكوين فرق الخبراء**:

- معادلة المطابقة متعددة المراحل.
- التطبيع والمقارنة بين المقاييس.
- بوابات الاستبعاد وقواعد التعويض.
- التنوع والتغطية عند تكوين الفريق.
- تحليل الحساسية للأوزان.
- تفسير النتيجة والإنصاف ومراقبة الانحياز.
- إعادة الترتيب بعد الاستيضاح أو تغير التوفر.
