# خطة الترحيل والتراجع V6

## قبل التنفيذ

1. نسخة احتياطية مشفرة واختبار استعادتها.
2. تشغيل جميع ملفات V5 في بيئة مماثلة للإنتاج.
3. قياس التكرار والمفاتيح اليتيمة والحالات غير المعروفة.
4. تثبيت إصدار التطبيق القديم خلال نافذة الترحيل.

## التنفيذ

1. تشغيل 0160 ثم 0170 ثم 0180 ثم 0190 باستخدام `ON_ERROR_STOP=1`.
2. تشغيل البذرة 006.
3. إجراء Smoke Tests للقراءة والكتابة والقيود.
4. نشر التطبيق بميزة Feature Flag للوحدات الجديدة.
5. مراقبة الأخطاء والأداء وسجل Outbox لمدة دورة تشغيل كاملة.

## التراجع

الترحيلات إضافية ولا تغير جداول V5؛ لذلك التراجع الافتراضي هو تعطيل Feature
Flags وإعادة التطبيق السابق مع إبقاء الجداول الجديدة. لا تسقط الجداول تلقائيًا.
إذا لزم حذفها، تؤخذ نسخة احتياطية مستقلة وتراجع الاعتماديات يدويًا في بيئة
صيانة معتمدة.

## ترحيل البيانات

لا تنسخ Party أو Account أو Membership. تربط السجلات الجديدة بالمفاتيح الحالية.
تُنقل المعرفة القديمة إلى `knowledge_assets` على دفعات idempotent مع جدول
مطابقة للمفاتيح، ثم تقارن الأعداد وchecksums قبل التحويل.
