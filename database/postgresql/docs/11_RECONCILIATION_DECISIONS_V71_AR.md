# مصفوفة مطابقة PostgreSQL الحالي مع النموذج المستهدف — V71

**المرجع:** النموذج المنطقي V70 وقاموس البيانات المركزي V70  
**الغرض:** تحويل الخط الأساس المفاهيمي إلى قرارات ترحيل قابلة للتنفيذ دون حذف.

## 1. نتيجة الجرد

- جرى جرد **294 جدولًا حاليًا** من ملفات migrations.
- أضيفت **16 بنية مستهدفة** لا توجد بصورتها النهائية حاليًا.
- كل جدول حالي له قرار صريح في الملف المرافق
  `11_CURRENT_TARGET_RECONCILIATION_V71.csv`.
- لا يوجد جدول مصنف `RETIRE` مباشرة؛ الإيقاف لا يبدأ إلا بعد النسخ الخلفي
  والمقارنة وفترة التوافق.

## 2. معنى قرارات المطابقة

| القرار | المعنى التنفيذي |
|---|---|
| `KEEP` | إبقاء الجدول واسمه وملكيته مع تحسين القيود عند الحاجة |
| `RENAME` | إنشاء الاسم المستهدف ثم واجهة توافق للاسم القديم |
| `MOVE` | نقل الملكية إلى مخطط أنسب دون فقد المعرفات |
| `SPLIT` | فصل سجل متعدد المعاني إلى سجلين واضحين |
| `MERGE` | توحيد جداول متكررة في مصدر حقيقة واحد |
| `ADD` | إضافة بنية مفقودة |
| `RETIRE` | إيقاف بنية قديمة بعد إثبات اكتمال الترحيل فقط |

## 3. القرارات الحرجة المعتمدة

### 3.1 هوية العميل

| الحالي | القرار | المستهدف |
|---|---|---|
| `crm.client_accounts` | `KEEP` | علاقة العميل التجارية المرتبطة بـ Party |
| `crm.client_organizations` | `MERGE` | `core.organizations + crm.client_accounts` |
| `crm.client_contacts` | `RENAME` | `crm.client_contact_roles` |

لا ينسخ CRM الاسم القانوني أو هوية المنظمة أو الشخص. تبقى الهوية في `core`,
ويبقى في CRM دور الاتصال، والتفويض، وملكية العلاقة، والتفضيلات والتاريخ.

### 3.2 الخبرات المهنية

تدمج جداول:

- `employment_experiences`
- `project_experiences`
- `training_experiences`
- `consulting_experiences`
- `research_experiences`

في `professional.experience_records` مع `experience_type_code` وحقول مشتركة،
مع جداول تفاصيل نوعية عند الحاجة. تحتفظ المعرفات القديمة في
`legacy_source_table` و`legacy_source_id` لضمان التتبع.

### 3.3 التدريب

| الحالي | القرار | المستهدف |
|---|---|---|
| `training.courses` | `RENAME` | `training.course_contents` |
| `training.course_names` | `MERGE` | `training.course_content_versions` |
| `training.course_versions` | `RENAME` | `training.course_content_versions` |
| `training.course_offerings` | `KEEP` | الطرح التشغيلي المستقل |
| `training.course_delivery_rights` | `MOVE` | `rights.course_delivery_rights` |
| `training.course_reviews` | `MOVE` | `quality.training_evaluations` |

يبقى منع الازدواجية على هوية المحتوى، بينما يسمح بتعدد الطروحات والمراكز
والمدربين والأسعار والمواعيد.

### 3.4 العقود والحقوق

- تنقل جداول `finance.contract_*` إلى مخطط `contract`.
- تنقل جداول `finance.ip_*` و`confidentiality_agreements` إلى `rights`.
- تبقى الفواتير والمدفوعات والاستردادات والتسويات داخل `finance`.
- تحفظ المفاتيح UUID نفسها أثناء النقل، وتوفر Views توافقية مؤقتة.

### 3.5 الجودة والسمعة

تنقل التقييمات والسمعة والشكاوى والاستئناف من `evidence` إلى `quality`.
يبقى `evidence` مسؤولًا عن الدليل والادعاء والتحقق ودرجة اليقين فقط.
تقسم الإجراءات التصحيحية بين:

- `governance.audit_corrective_actions`
- `quality.corrective_actions`

بحسب مصدر الإجراء، مع منع ازدواجية الملكية.

## 5. قواعد مطابقة الحقول

1. كل معرف حالي يبقى صالحًا؛ لا يعاد توليد UUID أثناء النقل.
2. `*_code` يرتبط بقائمة مرجعية أو قيد تحقق.
3. البريد والهاتف لا يدمجان في حقل واحد.
4. الدول ISO 3166-1 alpha-2، العملات ISO 4217، واللغات BCP 47.
5. المبالغ الجديدة `amount_minor bigint + currency_code`.
6. كل حقل JSON يحمل `schema_version` أو ينقل إلى أعمدة مضبوطة.
7. الحالة الحالية تحفظ في الأصل، وكل انتقال في جدول تاريخ append-only.
8. الملف لا يخزن داخل الجدول التجاري؛ يخزن مرجعه في `core.files`.
9. الخصوصية تطبق على الحقل والملف، لا على الشاشة فقط.
10. الحقول المشتقة تحمل النموذج والإصدار ووقت الحساب.

## 6. ترتيب حزم الترحيل

### الحزمة A — تأسيس غير هادم

- إنشاء مخططات `contract`, `rights`, `quality`.
- إنشاء الجداول المضافة.
- إضافة أعمدة الربط والتتبع والفهارس دون تغيير القراءة الحالية.

### الحزمة B — الهوية وCRM

- ربط كل عميل بـ Party واحد.
- كشف ودمج المنظمات المكررة.
- تحويل جهات الاتصال إلى علاقات أدوار.

### الحزمة C — المهنية والتدريب

- إنشاء `experience_records` والنسخ الخلفي.
- إنشاء هوية محتوى الدورة ونسخها.
- إبقاء الطروحات مستقلة وربط الحقوق والتقييم.

### الحزمة D — العقود والحقوق والجودة

- نسخ الجداول إلى مخططاتها الجديدة بالمعرفات نفسها.
- تشغيل القراءة المزدوجة والمقارنة.
- تفعيل Views توافقية للأسماء القديمة.

### الحزمة E — المال والمشاريع والحوكمة

- إضافة دفتر القيود وتوزيع الإيرادات.
- إضافة خطوط الأساس والقبول والتقدم والمساهمات.
- تسجيل قرارات الوصول والقرارات الآلية.

### الحزمة F — التحويل والإيقاف

- تحويل API إلى الأسماء المستهدفة.
- إيقاف الكتابة القديمة.
- فترة مراقبة وتوفيق.
- تصنيف الجداول القديمة `RETIRE` بعد موافقة صريحة واختبار الرجوع.

## 7. بوابات السلامة

لا تنتقل أي حزمة إلى الإنتاج ما لم يتحقق:

- تطابق عدد السجلات والمجاميع المالية.
- عدم وجود مفاتيح أجنبية يتيمة.
- تطابق عينات المحتوى والملفات والخصوصية.
- نجاح إعادة التشغيل دون إنشاء نسخ مكررة.
- نجاح التراجع إلى النسخة السابقة.
- نجاح اختبارات API والصلاحيات ومسارات المستخدم.
- وجود سجل تدقيق لكل دمج أو تغيير ملكية.

## 8. المخاطر ذات الأولوية

| الخطر | الضبط |
|---|---|
| دمج عميلين مختلفين خطأ | درجات تشابه + مراجعة بشرية قبل الدمج |
| فقد علاقة أثناء توحيد الخبرات | حفظ المصدر والمعرف القديم |
| كسر API بسبب نقل المخطط | Views وواجهات توافق |
| اختلاف رصيد مالي | مطابقة إجماليات وقيد عكسي، لا تعديل مباشر |
| نقل ملف دون قرار خصوصية | فحص الخصوصية قبل إتاحة القراءة |
| احتساب سمعة بنموذج قديم | حفظ إصدار النموذج مع كل Snapshot |

## 9. قرار التنفيذ

المصفوفة جاهزة لتوليد migrations، لكن الخطوة التالية ليست حذف الجداول؛ بل
إعداد **حزمة A التأسيسية غير الهادمة** مع DDL واختبارات تحقق وتراجع مستقلة.
