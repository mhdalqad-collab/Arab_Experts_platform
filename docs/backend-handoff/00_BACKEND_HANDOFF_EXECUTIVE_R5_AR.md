# الحزمة التنفيذية لتسليم Backend — EIM V113 R5

## الغرض

هذه الحزمة هي المرجع الملزم لبدء تطوير Backend. وهي تربط متطلبات V113
بالمخطط الإنتاجي وعقود API وقرارات الهوية والخصوصية والتكاملات ومعايير القبول.

## القرار التنفيذي

- PostgreSQL 16 هو مصدر الحقيقة الإنتاجي لجميع بيانات الأعمال.
- D1 الحالي طبقة عرض وانتقال مؤقتة فقط، ولا تُضاف إليه مجالات أعمال جديدة.
- تنفذ خدمات Backend العقود المنشورة في `openapi/eim-v113-r5.yaml`.
- لا يُقبل أي Endpoint دون Authorization خادمي، validation، audit، واختبار سلبي.
- الملفات تحفظ في Object Storage خاص، وتبقى metadata وحقوق الوصول في PostgreSQL.
- التفعيل يتم تدريجياً حسب المجالات، مع منع الكتابة المزدوجة غير المحكومة.

## بوابات البدء

1. اعتماد ADR-001 من مالك المنتج والمعماري ومطور Backend.
2. إنشاء PostgreSQL 16 في بيئة تطوير مع مستخدم migration منفصل.
3. تطبيق السلسلة كاملة وتشغيل اختبارات SQL.
4. اعتماد مزود الهوية والتخزين والبريد والدفع والتوقيع.
5. تثبيت OpenAPI قبل تطوير كل مجال، وتحديثه عبر مراجعة تغيير رسمية.

## ما يمكن البدء به فوراً

- تأسيس CI وقاعدة PostgreSQL ومشغل migrations.
- بناء طبقة الهوية والأطراف والعضويات.
- توليد نماذج API والتحقق من OpenAPI.
- تنفيذ Authorization مركزي وAudit middleware.
- تجهيز Object Storage الخاص وروابط الملفات الموقعة.

## ما لا يجوز افتراضه

- لا تعد ترويسة البريد الحالية مزود هوية إنتاجياً.
- لا تعد بيانات D1 الحالية المصدر النهائي.
- أسعار الباقات الصفرية ليست أسعاراً تجارية.
- نجاح الاختبارات المحلية لا يساوي قبول الأمن والأداء وUAT.
