# الخطة الرئيسية لاختبار قبول المستخدم UAT

## الهدف

إثبات أن المنصة تحقق رحلات MVP وصلاحياتها ونتائجها التشغيلية على بيئة مماثلة للإنتاج، باستخدام بيانات اختبار لا تتضمن معلومات شخصية حقيقية.

## الأدوار

- زائر عام.
- عضو/خبير يدير ملفه وأدلته وخصوصيته.
- مراجع عضوية.
- متخذ قرار عضوية مستقل عن المراجع.
- مراجع أدلة.
- مراجع نشر مهني ومتخذ قرار نشر.
- مشغل الإشعارات.
- مدير منصة بصلاحيات محددة.

## دورات الاختبار

1. **Smoke:** الصحة، الهوية، فتح الواجهة، الاتصال بقاعدة البيانات.
2. **الوظائف الأساسية:** التسجيل، العضوية، الملف، الأدلة، الخصوصية، البحث، النشر.
3. **الصلاحيات السلبية:** محاولة الوصول دون Permission أو Step-up أو خارج نطاق الجهة.
4. **التكامل:** OIDC والتخزين والفحص والإشعارات.
5. **الاعتمادية:** التكرار، التعارض، انتهاء الجلسة، انقطاع مزود خارجي.
6. **القبول التشغيلي:** النسخ الاحتياطي، الاستعادة، المراقبة، Rollback، الدعم.

## شروط النجاح

- نجاح 100% من حالات P0.
- عدم وجود عيب أمني أو فقد بيانات مفتوح.
- نجاح 95% على الأقل من P1 مع خطة معتمدة للباقي.
- توثيق كل نتيجة بصورة أو سجل أو Correlation ID.
- توقيع ممثل الأعمال والأمن والتشغيل.

## إدارة العيوب

| الدرجة | التعريف | قرار الإصدار |
|---|---|---|
| P0 | اختراق صلاحية، فقد بيانات، توقف رحلة أساسية | NO-GO |
| P1 | وظيفة أساسية خاطئة دون بديل مقبول | NO-GO ما لم تعالج وتعاد تجربتها |
| P2 | خلل محدود مع بديل موثق | قرار لجنة الإصدار |
| P3 | تحسين أو مشكلة شكلية | يمكن ترحيله للـBacklog |
