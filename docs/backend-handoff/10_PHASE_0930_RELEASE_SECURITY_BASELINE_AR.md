# المرحلة 0930 — هندسة الإصدار وخط الأساس الأمني

تاريخ التنفيذ: 2 أغسطس 2026

## خط الإصدار الآلي

أضيف Workflow يطبق عند Pull Request والدفع إلى `main`:

1. تثبيت الاعتماديات المثبتة في `package-lock.json`.
2. ESLint وTypeScript والاختبارات العامة.
3. اختبارات Backend.
4. تشغيل PostgreSQL 16 واختبارات التكامل والترحيلات.
5. فحص خط الأساس الأمني.
6. `npm audit` للثغرات العالية في اعتماديات الإنتاج.
7. إنشاء CycloneDX SBOM.
8. حفظ SBOM وعقود OpenAPI كأدلة إصدار.
9. بناء صور Frontend وBackend.

## خط الأساس الأمني

- منع تشغيل الحاويات بصلاحيات root.
- عدم نشر شبكة قاعدة البيانات.
- منع Reverse Proxy من تمرير `/internal/` خارجيًا.
- TLS 1.2/1.3 وHSTS ورؤوس أمنية.
- Rate limiting وحد اتصال وحجم طلب 11MB.
- فحص أنماط الأسرار الإنتاجية الشائعة.
- منع `eval` و`new Function` في المصدر التشغيلي.
- التحقق من OpenAPI ضمن بوابة الأمن.

## استمرارية البيانات

- Backup بصيغة PostgreSQL custom مع SHA-256 وفحص بنيوي.
- الاستعادة لا تعمل إلا مع تصريح صريح وقاعدة فارغة قابلة للتخلص.
- رفض تعديل قاعدة تحتوي جداول مستخدم.
- التحقق بعد الاستعادة من PostgreSQL 16 ومن عدد الجداول المتوقع.

## نتيجة التحقق المحلي

- Bash syntax: ناجح.
- Security baseline: ناجح.
- YAML لـCI وCompose: صالح.
- OpenAPI: ناجح بانحراف صفري.
- دعم npm SBOM: متوفر.
- Docker build وPostgreSQL restore rehearsal وCI hosted run: تنتظر بيئة تشغيل فعلية.
