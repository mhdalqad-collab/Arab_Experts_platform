# النموذج المنطقي الموحد — EIM 6 / V70

**المرجع:** EIM-CB-002  
**الحالة:** خط أساس منطقي معتمد للمطابقة مع DDL، دون تغييرات هادمة.

## 1. مبادئ البناء

يقسم النموذج الجداول إلى ثلاثة أنماط:

1. **جداول الهوية الثابتة:** تمثل الشخص أو المنظمة أو الحساب مرة واحدة.
2. **جداول النسخ:** تحفظ المحتوى القابل للمراجعة والنشر والإصدار.
3. **جداول الحدث والتاريخ:** تحفظ الانتقالات والقرارات والتدقيق ولا يعاد كتابتها.

تعتمد الأسماء `snake_case`، والجداول بصيغة الجمع، والمفاتيح الداخلية `uuid`.
تستخدم الحقول المرجعية اللاحقة `_id`، والرموز المضبوطة اللاحقة `_code`،
والأزمنة `timestamptz`، والتواريخ المدنية `date`. تحفظ القيم المالية الجديدة
في `amount_minor bigint` مع رمز عملة ISO، مع إبقاء `numeric(18,3)` مؤقتًا
للجداول القائمة إلى حين ترحيلها.

## 3. الهوية والحساب والعضوية

السلسلة المرجعية الوحيدة هي:

`iam.user_accounts → core.persons → core.parties → membership.memberships`

- لا يوجد `expert`, `trainer`, `consultant`, `researcher`, `client` كنوع Party.
- هذه صفات مهنية أو عضويات متعددة للشخص نفسه.
- المنظمة Party واحدة، ويمكن أن تكون عميلًا ومركز تدريب ومالك محتوى في الوقت نفسه.
- البريد والهاتف والعنوان كيانات اتصال مستقلة، وتطبق الخصوصية على كل بيان.
- يمنع إنشاء حسابين نشطين للبريد الموثق نفسه، أو شخصين للهوية الموثقة نفسها.

## 4. الملف المهني والبصمة

يرتبط الملف المهني بالعضوية، وتفصل عنه السجلات المتكررة:

- المؤهلات والاعتمادات.
- الخبرات والمشاريع.
- التخصصات الرئيسية والفرعية والممارسات التفصيلية.
- اللغات ومستويات الإتقان.
- الأدوار والخدمات وأنماط التسليم.
- التوفر والأسعار.

يقترح توحيد الخبرات المتفرقة في `professional.experience_records` مع نوع مضبوط،
مع إبقاء الجداول الحالية كواجهات توافق خلال الترحيل. البصمة المهنية نسخة مشتقة
قابلة لإعادة الحساب، ولا تعد مصدر الحقيقة للخبرات الأصلية.

## 5. الأنطولوجيا والتصنيف

يعتمد `taxonomy.concepts` كمصدر واحد للمجال والتخصص والممارسة والمحتوى التفصيلي.
يضاف تاريخ حالة المفهوم، ودليل قرار الربط، ونسخة خريطة الربط بين التصنيف المهني
والتدريبي. تمنع القيود الحلقات والتبعية الذاتية والعلاقات خارج النسخة المنشورة.

## 6. الأدلة واليقين

الدليل أصل مستقل، ويرتبط بادعاء محدد، ثم تمر عليه عملية تحقق تنتج نتيجة ودرجة
يقين وتاريخ صلاحية. تستبدل الروابط متعددة الأشكال غير المقيدة تدريجيًا بجداول
ربط صريحة لكل عائلة كيان حتى تضمن المفاتيح الأجنبية سلامة المرجع.

## 7. القدرات والخدمات والعروض

`Capability` تثبت ما يستطيع الطرف فعله، و`ServiceDefinition` تعرف الخدمة،
و`ServiceOffering` يمثل عرضًا قابلًا للطلب والتسعير. لا تعد الخبرة عرضًا،
ولا يعد العرض دليلًا على القدرة إلا بربطه بالبصمة والأدلة.

## 8. العميل والاحتياج والمطابقة

### منع تكرار العميل

لا تنشئ CRM شخصًا أو منظمة جديدة. يشير `crm.client_accounts.party_id` إلى
`core.parties`، ويحتفظ CRM بالعلاقة التجارية والمالك الداخلي والتصنيف فقط.
تدمج `client_organizations` في علاقة Party أو تجعل واجهة توافق، وتربط جهات
الاتصال بأشخاص موجودين وبعلاقة مؤسسية واضحة.

طلب الخدمة كيان مستقل عن العميل، وله نسخة بصمة، ونطاق، وميزانية، وجدول زمني،
ومخرجات، وقيود، ومعايير موزونة. كل تشغيل مطابقة يحفظ نسخة المدخلات والخوارزمية
والنتائج والتفسيرات والقائمة المختصرة وقرار العميل.

## 9. التدريب

تفصل المنظومة بين:

- `course_contents`: هوية المحتوى ومنع الازدواجية.
- `course_content_versions`: النسخ والتحرير والاعتماد.
- `course_offerings`: طرح محدد بمركز ومدرب ووقت ونمط وسعر.
- `course_instructors`: إسناد المدربين مع الدور.
- التسجيل والحضور والتقييم والشهادة.

يربط المحتوى بالتصنيف 7×7×7، والفئة المستهدفة، واللغة، والمالك، والترخيص.
لا يؤدي ربط مدرب أو مركز بالمحتوى إلى نقل الملكية.

## 10. العقود والمشاريع والتسليم

يوجد **عقد واحد مشترك** يمكن أن يغطي خدمة أو مشروعًا أو تدريبًا أو اشتراكًا،
وتلحق به الأطراف والبنود والملاحق والتوقيعات والفواتير. المخطط المستهدف
للعقود هو `contract` بدل وضعها ضمن `finance`.

تضاف للمشروع:

- خط أساس النطاق والوقت والتكلفة.
- معايير قبول قابلة للقياس.
- أوامر تغيير مع أثرها وموافقاتها.
- تقارير تقدم.
- مساهمات أعضاء الفريق.
- تسليمات ونسخها ومراجعاتها وقبولها.

## 11. البحث والمعرفة والفعاليات

تفصل هوية العمل البحثي عن نسخه ومنشوراته ومساهميه وحقوقه. أصل المعرفة قد ينتج
عن مشروع أو دورة أو بحث، وله إصدار وحالة نشر وتصنيف وصلاحية وصول. الفعالية
كيان مستقل، وقد تربط بدورة أو منشور دون دمجهما.

## 12. الحقوق والسرية

المخطط المستهدف `rights` يملك:

- حقوق الملكية والتأليف.
- التراخيص ونطاقها ومدتها.
- اتفاقات السرية والأطراف المشمولة.
- تصنيف المعلومات وقيود الاستخدام.
- سجل الإفصاح المصرح.

تنقل جداول `finance.ip_*` واتفاقات السرية ترحيلًا غير هادم عبر جداول جديدة
وواجهات توافق ثم مقارنة وعدّ السجلات قبل إيقاف القديمة.

## 13. المال والاشتراك

تفصل الخطة عن الاشتراك، والفاتورة عن الدفع، والاسترداد عن إلغاء الاشتراك.
يحفظ كل قيد مالي بعملة ومبلغ ووحدة صغرى، ويمنع تعديل الحركة المرحّلة؛ التصحيح
يتم بحركة عكسية. ترتبط توزيعات الإيراد بالمصدر والعقد والمستفيد.

## 14. الجودة والسمعة والشكاوى

المخطط المستهدف `quality` يفصل التقييم الخام عن الدرجة المجمعة، والسمعة عن
التقييم، والشكوى عن الحكم، والإجراء التصحيحي عن قرار الشكوى. لا تورث سمعة
المركز إلى المدرب ولا العكس دون قاعدة معلنة وأثر قابل للتفسير.

## 15. الحوكمة والخصوصية والأمن

تطبق الصلاحية من الدور + المورد + النطاق + الغرض + قرار الخصوصية. تحفظ
الموافقات وإصدارات السياسات وطلبات أصحاب البيانات وقرارات الوصول وسجل التدقيق.
كل قرار آلي مؤثر يحفظ النموذج والإصدار والمدخلات والتفسير ومسار الاعتراض.

## 16. الأحداث والتكامل

تستخدم المنصة نمط **Transactional Outbox**: يحفظ تغير الحالة والحدث الصادر في
المعاملة نفسها، مع `aggregate_type`, `aggregate_id`, `event_type`,
`schema_version`, `occurred_at`, `idempotency_key` وحالة التسليم. المستهلك
يعالج الحدث بصورة idempotent.

## 17. الحذف والاحتفاظ

الأرشفة المنطقية هي الأصل للكيانات التجارية. تمنع إزالة السجل إذا كان مطلوبًا
لعقد أو حركة مالية أو تدقيق أو نزاع. يطبق إخفاء/تقليل البيانات الشخصية وفق
الأساس القانوني وسياسة الاحتفاظ، دون كسر السجل المحاسبي.

## 18. قيود مشتركة

- فهارس فريدة جزئية للكيانات النشطة.
- `check` للمبالغ غير السالبة والمدد الصحيحة والنسب ضمن مداها.
- مفاتيح أجنبية تمنع السجلات اليتيمة.
- سجل انتقال لكل كيان نحوري، مع منع القفز بين الحالات.
- حقول مشتقة تحمل مصدر الاشتقاق وإصداره ووقت الحساب.
- حقول JSON تحمل `schema_version` وتتحقق في طبقة الخدمة.

## 19. استراتيجية التوافق والترحيل

لا يعاد بناء القاعدة دفعة واحدة. تصنف كل بنية حالية إلى:

`KEEP`، `RENAME`، `MOVE`، `SPLIT`، `MERGE`، `ADD`، `RETIRE`.

ثم تنفذ الإضافات، والنسخ الخلفي، والقراءة المزدوجة عند الحاجة، والمقارنة،
والتحويل، وفترة التوافق، وأخيرًا الإيقاف. يمنع أي إسقاط قبل نجاح اختبارات العد
والعلاقات والتراجع.

## 20. بوابة DDL التالية

قبل إصدار أي migration جديد يجب استكمال مصفوفة جدول/عمود/قيد من الوضع الحالي
إلى المستهدف، وتحديد مالك البيانات، وأثر API والواجهة والصلاحية والاختبار،
وخطة الرجوع لكل تغيير.
