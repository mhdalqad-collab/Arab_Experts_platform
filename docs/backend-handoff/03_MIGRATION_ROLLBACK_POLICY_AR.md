# سياسة Migration وRollback — V113 R5

## التسلسل القياسي

1. نسخة احتياطية واختبار قابلية الاستعادة.
2. تشغيل migrations الستين بالترتيب الاسمي عبر `run-all.sh --migrations-only`.
3. تنفيذ smoke queries وفحص `integration.schema_migrations`.
4. تشغيل seeds السبعة عبر `run-all.sh --seeds-only` في البيئات المسموح بها.
5. تشغيل اختبارات SQL والتنافس.
6. حفظ بصمة الإصدار والنتائج ضمن سجل النشر.

## التصنيف

- migrations التأسيسية `0000–0190` تعد baseline ويفضل إصلاحها forward-only بعد الإنتاج.
- migrations `0200–0560` لها ملفات rollback حيث يكون التراجع البنيوي آمناً.
- غياب rollback لا يعني السماح بالحذف اليدوي؛ يلزم forward-fix أو restore محكوم.

## قواعد إلزامية

- لا تعدل migration سبق نشرها إنتاجياً؛ يضاف migration تصحيحي جديد.
- لا تستخدم `DROP` أو تغييراً هادماً دون خطة بيانات وموافقة مستقلة.
- كل migration تعمل داخل transaction متى سمحت PostgreSQL.
- لا تطبق seeds التجارية المؤقتة على الإنتاج دون اعتماد مالك البيانات.
- أسعار الباقات الصفرية placeholder وليست سياسة سعرية.

## قرار التراجع

| الحالة | الإجراء |
|---|---|
| فشل قبل commit | توقف آلي وإصلاح السبب |
| فشل بعد schema مع عدم وجود بيانات جديدة | rollback معتمد إن توفر |
| بيانات إنتاج جديدة بعد الترقية | forward-fix أو استعادة إلى بيئة بديلة |
| خلل تطبيق دون خلل بيانات | rollback للتطبيق مع إبقاء schema المتوافق |
| فقد/فساد بيانات | تفعيل خطة الاستعادة والتحقيق؛ يمنع الارتجال |

## الأدلة المطلوبة

- سجل أوامر النشر والنسخة والمنفذ والتوقيت.
- نتيجة 60/60 migrations و7/7 seeds عند الحاجة.
- نتائج smoke وintegration وconcurrency.
- زمن الاستعادة الفعلي ومطابقته RTO/RPO.
