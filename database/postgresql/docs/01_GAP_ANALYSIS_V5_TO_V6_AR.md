# تحليل فجوات PostgreSQL V5 إلى V6

## 1. خلاصة القرار

لا تُستبدل V5 ولا تُعاد تسمية كياناتها الأساسية. تبقى `core.parties` مصدر الحقيقة
الموحد للأشخاص والمنظمات، وتضاف V6 كتوسعة تراكمية عبر الترحيلات 0160–0190.

## 2. الفجوات التي أغلقتها V6

| المجال | وضع V5 | معالجة V6 |
|---|---|---|
| البحث العلمي | معرفة عامة محدودة | مشاريع بحث، أطراف، تصنيف، منشورات وإصدارات ومراجعة أقران |
| الفعاليات | غير ممثل كنطاق مستقل | فعاليات، جلسات، مشاركون، تسجيل، حضور وتصنيف |
| إدارة المعرفة | دروس مستفادة فقط | أصل معرفي موحد، إصدارات، ملفات، علاقات، تصنيف واستخدام |
| RBAC | أدوار تشغيلية ضمنية | أدوار وصلاحيات وإسناد مقيد بالنطاق والتفويض والمراجعة |
| فصل المهام | غير محكوم | قواعد SOD واعتمادات متعددة ومنع الاعتماد الذاتي |
| الخصوصية | تفضيلات متفرقة | تصنيف بيانات، غرض، موافقة مؤرخة وخصوصية على مستوى الحقل |
| التدقيق | سجل غير مكتمل | أحداث append-only، سلسلة hash، حالات تدقيق وإجراءات تصحيح |
| التكامل | لا عقود بيانات محكومة | أنظمة واتصالات وعقود بيانات وإصدارات وخرائط وOutbox/Inbox |

## 3. ما لا يجوز إعادة بنائه

- الأشخاص والمنظمات والحسابات والعضويات.
- التصنيف المهني والتدريبي الحالي وإصداراته.
- الأدلة والخدمات والدورات والعملاء والاحتياجات والمطابقة والتسليم.
- العقود والملكية الفكرية والفوترة.

## 4. فجوات تشغيلية تبقى خارج DDL

- موفر هوية وإرسال بريد/OTP فعلي.
- بوابة دفع وربط Webhook فعلي.
- مخزن ملفات وفحص برمجيات ضارة.
- محرك بحث وفهرسة، ومحرك مهام غير متزامنة.
- سياسات RLS الفعلية بعد تثبيت هوية جلسة التطبيق.
- مراقبة وتشغيل نسخ احتياطي واستعادة في بيئة فعلية.
