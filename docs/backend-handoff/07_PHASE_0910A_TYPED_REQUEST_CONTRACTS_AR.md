# المرحلة 0910A — تشديد عقود طلبات Backend API

تاريخ التنفيذ: 2 أغسطس 2026

## الهدف

إلغاء مخطط `JsonCommand` العام وربط كل عملية تقرأ JSON بمخطط يعكس دالة التحقق الفعلية في Backend.

## النتيجة

- تغطية 48 عملية تقرأ JSON.
- إنشاء 41 مخطط Command مستقلًا وقابلًا لإعادة الاستخدام.
- تحديد الحقول المطلوبة والاختيارية.
- تطبيق الأنواع والحدود العددية وحدود الأطوال.
- توثيق UUID والتواريخ وSHA-256.
- توثيق القيم المسموحة للقرارات والحالات الحساسة.
- رفض الخصائص غير المعروفة في المستوى الأعلى عبر `additionalProperties: false`.
- عدم إنشاء `requestBody` للعمليات التي لا تقرأ جسم طلب.
- تحديث مولّد OpenAPI إلى `1.0.0-r5.0910a`.

## بوابة منع الانحراف

يفشل `npm run validate:openapi` تلقائيًا عند حدوث أي مما يلي:

- إضافة عملية تقرأ JSON دون دالة Parse معروفة.
- وجود دالة Parse دون مخطط OpenAPI مقابل.
- اختلاف عدد عمليات JSON المنفذة عن العقود الموثقة.
- عودة `JsonCommand` العام أو مخطط عام غير مضبوط.
- اختلاف العقد المولد عن الملف المحفوظ.
- وجود مسار ناقص أو زائد أو `operationId` مكرر.

## التحقق المنفذ

- OpenAPI 3.1: صالح نحويًا للعقدين.
- Same-Origin: 22 مسارًا و52 عملية.
- Backend: 82 مسارًا و90 عملية.
- انحراف المسارات: صفر.
- Typed request bodies: 48/48.
- Command schemas: 41.
- فحص JavaScript للمولد والمدقق: ناجح.
- اختبارات Backend التي لا تحتاج الاعتمادية الخارجية `jose`: ‏50/50 ناجحة من البناء المحفوظ.

إعادة بناء TypeScript وتشغيل مجموعة الاختبارات 52/52 يتطلبان تنفيذ `npm run install:ci` أولًا؛ لأن الحزمة الأرشيفية تستبعد `node_modules` عمدًا. كانت المجموعة الكاملة 52/52 ناجحة قبل الأرشفة في المرحلة 0900، ولم تُعدّل ملفات Backend TypeScript في 0910A.

## الجزء التالي 0910B

تخصيص مخطط `data` للاستجابة الناجحة لكل عملية، مع توثيق حالات 400 و404 و409 و413 و415 و503 وأمثلة الاستجابة وقواعد Pagination.
