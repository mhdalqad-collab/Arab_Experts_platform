# EIM-GPSAI-001 — الحوكمة والخصوصية والأمن والتدقيق والتكاملات

**الحالة:** مواصفة مفاهيمية ختامية للحدود المؤسسية  
**الإصدار:** 1.0  
**النطاق:** سلطة القرار، السياسات، الصلاحيات، الخصوصية، إدارة الهوية والوصول، الأمن، الحوادث، التدقيق، التكاملات وحوكمة الذكاء الاصطناعي

## 1. الغرض والحدود

تحدد هذه المواصفة من يملك القرار، وكيف تتحول السياسات إلى ضوابط قابلة للتنفيذ، وكيف تحمى البيانات والعمليات وتراجع دون منح مدير المنصة سلطة غير محدودة.

> **الدور ليس صلاحية مطلقة، والموافقة ليست الأساس القانوني الوحيد، وسجل التدقيق ليس نسخة احتياطية.**

الحوكمة تحدد السلطة والمساءلة؛ الخصوصية تحكم الاستخدام المشروع للبيانات؛ الأمن يحمي السرية والسلامة والتوافر؛ والتدقيق يثبت ما حدث. لا يحل أي منها محل الآخر.

## 2. مبادئ الحوكمة

1. وضوح الملكية والمساءلة.
2. أقل صلاحية وحاجة إلى المعرفة.
3. فصل الواجبات والرقابة المزدوجة.
4. تناسب الضوابط مع المخاطر.
5. الشفافية وقابلية التفسير.
6. الخصوصية والأمن منذ التصميم.
7. عدم الحذف الصامت للسجلات الجوهرية.
8. حق الاعتراض والمراجعة البشرية.
9. توثيق الاستثناءات وانتهاؤها.
10. التحسين المبني على الأدلة.

## 3. هيكل السلطة

| الهيئة/الدور | المسؤولية |
|---|---|
| مجلس/مالك المنصة | التوجه والمخاطر المقبولة والسياسات العليا |
| لجنة الحوكمة | اعتماد السياسات والتعارضات والاستثناءات الجوهرية |
| مالك المجال | تعريف قواعد الأعمال وجودة بيانات المجال |
| مالك المنتج | الأولويات وتجربة المستخدم ضمن السياسة |
| مسؤول الخصوصية | الأغراض والأسس والحقوق وتقييم الأثر |
| مسؤول الأمن | المخاطر والضوابط والحوادث |
| مسؤول البيانات | الجودة والتصنيف والاحتفاظ |
| مسؤول التدقيق | ضمان مستقل وفحص الأثر |
| مدير النظام | تشغيل تقني بلا سلطة أعمال تلقائية |
| المشغل | إجراء مخول ضمن قائمة مهام وحدود |

لا يجوز لمدير النظام منح نفسه صلاحية أعمال أو اعتماد الإجراء الذي نفذه.

## 4. دورة حياة السياسة

`مقترحة → قيد المراجعة → معتمدة → منشورة → نافذة → قيد المراجعة الدورية → مستبدلة | متقاعدة`

كل سياسة تحمل:

- المالك والجهة المعتمدة.
- النطاق والجمهور.
- تاريخ النفاذ والمراجعة.
- الالتزامات والضوابط والاستثناءات.
- ارتباطها بالمتطلبات والقواعد والاختبارات.
- الإصدار السابق وأثر التغيير.

لا تطبق سياسة بأثر رجعي إلا بسند قانوني وقرار موثق.

## 5. الاستثناءات

الاستثناء ليس تجاوزًا شفهيًا. يجب أن يتضمن:

- القاعدة المستثناة.
- السبب والمخاطر.
- النطاق والمالك.
- الضوابط التعويضية.
- جهة الاعتماد.
- تاريخ انتهاء لا يترك مفتوحًا.
- مراجعة وإغلاق.

## 6. نموذج الوصول المتكامل

يستخدم القرار مزيجًا من:

- **RBAC:** الدور الوظيفي أو المؤسسي.
- **ABAC:** صفات المستخدم والبيانات والسياق.
- **ReBAC:** علاقة المستخدم بالمنظمة أو المشروع أو السجل.
- **Policy rules:** الغرض والوقت والموقع والجهاز والمخاطر.

`Permit = Role ∧ Relationship ∧ Purpose ∧ ResourcePolicy ∧ Context ∧ NoExplicitDeny`

الحظر الصريح يغلب السماح العام. ويعاد تقييم الوصول عند كل عملية حساسة، لا عند تسجيل الدخول فقط.

## 7. نطاقات الصلاحيات

تفصل الصلاحيات إلى:

- قراءة بيانات وصفية.
- قراءة المحتوى.
- إنشاء.
- تعديل مسودة.
- إرسال/نشر.
- اعتماد.
- مشاركة/تنزيل.
- إدارة صلاحيات.
- تصدير جماعي.
- تصحيح أو إبطال.

امتلاك «تعديل» لا يعني «اعتماد»، وامتلاك «قراءة» لا يعني «تنزيل أو مشاركة».

## 8. حسابات المنظمة والتفويض

- الحساب يخص هوية دخول، والعضوية تربطه بطرف أو منظمة.
- الدعوة لا تصبح وصولًا قبل قبولها والتحقق.
- لكل منظمة مالك واحد على الأقل.
- لا يمكن إزالة آخر مالك قبل تعيين بديل.
- التفويض يحمل نطاقًا ومدة وحدودًا مالية/تشغيلية.
- إنهاء عمل ممثل المنظمة يبطل وصوله دون حذف أفعاله السابقة.

## 9. إدارة الهوية والمصادقة

### مستويات ضمان الهوية

- **IAL1:** بيانات أساسية غير متحققة.
- **IAL2:** هوية موثقة بمستندات/مصدر موثوق.
- **IAL3:** تحقق معزز للعمليات عالية الحساسية.

### مستويات ضمان المصادقة

- كلمة مرور قوية أو دخول اتحادي.
- عامل ثانٍ للأدوار الحساسة.
- مصادقة مقاومة للتصيد للحسابات الإدارية والمالية عند الإمكان.
- تحقق تصاعدي قبل التوقيع أو الاسترداد أو تغيير بيانات التحويل.

## 10. استعادة الحساب

- لا تكشف الاستعادة وجود حساب أكثر من اللازم.
- تستخدم قناة متحققة ورمزًا محدود العمر والمحاولات.
- العملية عالية المخاطر تحتاج تحققًا إضافيًا حسب الدور.
- بعد نجاح الاستعادة، تبطل الجلسات السابقة والرموز الحساسة.
- يرسل إشعار مستقل ويمنح المستخدم مسار بلاغ إذا لم يطلب العملية.
- لا يستطيع الدعم معرفة كلمة المرور أو تجاوز التحقق منفردًا.

## 11. الجلسات والأجهزة

- للجلسة معرف ووقت إنشاء وآخر نشاط وجهاز تقريبي ومستوى مصادقة.
- تنتهي الجلسات غير النشطة وفق المخاطر.
- يستطيع المستخدم رؤية جلساته وإبطالها.
- تغير السياق أو الخطر يطلب إعادة المصادقة.
- الرموز قصيرة العمر وتدور رموز التجديد.
- لا توضع أسرار أو بيانات حساسة في عنوان الصفحة أو السجلات العامة.

## 12. حوكمة البيانات

لكل عنصر بيانات:

- مالك وأمين.
- تعريف ومعنى ومصدر.
- تصنيف حساسية.
- غرض وأساس معالجة.
- جودة وقواعد تحقق.
- نظام مرجعي ونسخ مشتقة.
- مدة احتفاظ.
- سياسة وصول وإفصاح.

السجل الموحد للطرف هو المرجع للهوية، ولا تنشأ نسخ مستقلة للخبير والمدرب والمستشار.

## 13. مبادئ الخصوصية

- تحديد الغرض.
- تقليل البيانات.
- الدقة والتحديث.
- تحديد الاحتفاظ.
- الشفافية.
- السرية والسلامة.
- المساءلة.
- الفصل بين البيانات العامة والمسموحة والمخفية.

لا يجمع حقل «احتياطًا» بلا غرض معتمد. ولا يستخدم غرض التسجيل لاحقًا في التسويق أو تدريب نموذج دون أساس مستقل.

## 14. سجل أنشطة المعالجة

يسجل لكل نشاط:

- الغرض والفئات والأطراف.
- الأساس القانوني.
- مصادر البيانات.
- المستلمين والتحويلات.
- الاحتفاظ.
- الضوابط.
- الحقوق وآلية ممارستها.
- تقييم المخاطر والأثر.

الموافقة أحد الأسس المحتملة وليست بديلًا افتراضيًا للعقد أو الالتزام القانوني أو المصلحة المشروعة حيث تنطبق.

## 15. الموافقة والتفضيلات

الموافقة الصحيحة:

- حرة ومحددة ومستنيرة وواضحة.
- منفصلة حسب الغرض عند اختلافه.
- مثبتة بالإصدار والنص والتاريخ.
- قابلة للسحب بسهولة مماثلة للمنح.

سحب الموافقة يوقف المعالجة المعتمدة عليها مستقبلًا، لكنه لا يمحو معالجة سابقة مشروعة أو التزام احتفاظ مستقل.

## 16. الخصوصية على مستوى الحقل

لكل بيان قابل للعرض:

- حالة العرض العام: نعم/لا.
- الجمهور المسموح.
- الغرض.
- مصدر القرار: صاحب البيانات أو عقد أو قانون.
- تاريخ السريان.
- استثناءات الإدارة المخولة.

«إظهار المعلومات المخفية لمدير المنصة» لا يعني عرضها لكل مشغل؛ يحتاج المشغل مهمة مخولة وغرضًا وسجل وصول.

## 17. حقوق صاحب البيانات

يدعم النظام:

- الوصول والحصول على نسخة.
- التصحيح.
- المحو حيث ينطبق.
- التقييد.
- الاعتراض.
- قابلية النقل عند انطباقها.
- معرفة الاستخدام والمصادر.
- الاعتراض على القرار الآلي المؤثر.

### دورة حياة الطلب

`مقدم → تحقق الهوية → فحص النطاق → قيد التنفيذ → رد → مكتمل | مرفوض مسببًا | مستأنف`

لا تكشف الاستجابة بيانات طرف آخر أو أسرارًا محمية.

## 18. الاحتفاظ والإتلاف

- تربط مدة الاحتفاظ بنوع السجل والغرض والالتزام.
- يبدأ الحساب من حدث واضح.
- يطبق تعليق الإتلاف عند نزاع أو تحقيق أو التزام قانوني.
- عند انتهاء المدة: حذف آمن أو إخفاء هوية مثبت.
- لا يعد تعطيل الحساب محوًا.
- تحتفظ سجلات التدقيق بالحد الأدنى اللازم دون إعادة نسخ المحتوى الحساس.

## 19. أمن البيانات

- تشفير أثناء النقل والتخزين للبيانات الحساسة.
- إدارة مفاتيح منفصلة ومقيدة ودورية.
- فصل بيئات التطوير والاختبار والإنتاج.
- منع استخدام بيانات إنتاج حساسة في الاختبار دون إخفاء مناسب.
- نسخ احتياطية مشفرة واختبار استعادة دوري.
- حماية الملفات من البرمجيات الضارة والتحقق من النوع والحجم.
- روابط تنزيل محدودة الزمن والنطاق.

## 20. التطوير الآمن

تطبق دورة التطوير:

1. متطلبات أمن وخصوصية.
2. نمذجة تهديد.
3. مراجعة تصميم.
4. فحص تبعيات وأسرار وشفرة.
5. اختبارات آلية ويدوية.
6. مراجعة تغييرات.
7. نشر مضبوط وإمكان تراجع.
8. مراقبة ومعالجة ثغرات.

لا ينشر تغيير لصلاحية أو معادلة مطابقة أو حركة مالية دون اختبار قبول مناسب.

## 21. إدارة الثغرات

- تسجل الأصول والإصدارات والتبعيات.
- تصنف الثغرة حسب القابلية للاستغلال والأثر والسياق.
- تحدد مهلة علاج وتصعيد.
- يعالج الاستثناء بمدة وضابط تعويضي.
- يتحقق من الإصلاح دون كشف تفاصيل استغلال للعامة.
- يوجد مسار إبلاغ مسؤول للباحثين والمستخدمين.

## 22. الحوادث الأمنية والخصوصية

### دورة حياة الحادث

`إشارة → تحقق → حادث مؤكد → احتواء → استئصال → استعادة → تقييم إخطار → إغلاق → مراجعة لاحقة`

يسجل:

- النطاق والأنظمة والبيانات.
- الخط الزمني.
- القرارات والأدلة.
- المتأثرين والمخاطر.
- الإخطارات والالتزامات.
- السبب الجذري والإجراءات التصحيحية.

لا تؤخر حماية السمعة المؤسسية إخطارًا واجبًا.

## 23. استمرارية الأعمال والتعافي

- تصنف العمليات حسب الأهمية.
- يحدد RTO وRPO لكل خدمة.
- توثق الاعتماديات ونقاط الفشل.
- تختبر الاستعادة والبدائل دوريًا.
- لا تعد النسخة الاحتياطية خطة استمرارية كاملة.
- تتضمن الخطة تشغيلًا يدويًا محدودًا واتصالًا بالأطراف.

## 24. سجل التدقيق

يسجل الحدث:

- من فعل أو حاول.
- الصفة والجهة المفوضة.
- ماذا وعلى أي مورد وإصدار.
- متى ومن أي سياق موثوق.
- القرار: سماح/منع.
- السبب والسياسة المستخدمة.
- القيم السابقة واللاحقة بالحد الآمن.
- معرف الارتباط للعملية.

> **سجل التدقيق يثبت الحدث ولا يمنح حق الاطلاع على المحتوى المسجل.**

يحمي من التعديل، يراقب الانقطاع، ويصدر التصحيح كحدث جديد لا بتغيير الحدث الأصلي.

## 25. المراقبة والتنبيه

- تراقب محاولات الدخول، والتصعيد، والتصدير، والتنزيل الجماعي، والتغييرات المالية والإدارية.
- التنبيه مؤشر يحتاج تحققًا، وليس حكمًا تلقائيًا.
- تقلل البيانات في التنبيه إلى ما يحتاجه فريق الاستجابة.
- تحفظ قواعد الكشف بإصدارات ويقاس أثر الإيجابيات الكاذبة.
- تمنع صلاحيات المشغل من تعطيل مراقبة أفعاله.

## 26. ضمان استقلال التدقيق

- يقرأ المدقق السجلات اللازمة دون قدرة على تعديلها.
- لا يدقق الشخص عمله وحده.
- تحفظ خطة التدقيق والنطاق والعينة والنتائج.
- لكل ملاحظة مالك وموعد وإجراء وتصنيف.
- لا تغلق الملاحظة قبل التحقق من التنفيذ والفعالية.
- يقبل الخطر المتبقي صاحب سلطة محدد، لا منفذ الإجراء.

## 27. التكاملات

كل تكامل يحمل:

- مالكًا وغرضًا ونظامًا خارجيًا.
- أنواع البيانات واتجاهها.
- أساس المشاركة وعقد المعالجة.
- آلية المصادقة والنطاقات.
- حدود الاستخدام والمعدل.
- قواعد التزامن والتكرار.
- التوفر والمراقبة.
- الاحتفاظ والإيقاف.

لا يحصل التكامل على صلاحية أوسع من حاجته، ولا يستخدم حساب مستخدم بشري مشترك.

## 28. واجهات API

- إصدار واضح وتوافق خلفي معلن.
- تحقق من المخطط والقيم والصلاحيات في الخادم.
- مفاتيح عدم تكرار للعمليات القابلة للتكرار.
- ترقيم صفحات وحدود معدلات.
- أخطاء لا تكشف أسرارًا أو بنية داخلية.
- معرف طلب للتتبع.
- منع تعداد الحسابات والمعرفات.
- توثيق دقيق للحقول والخصوصية.

## 29. Webhooks

- توقيع رقمي وتحقق من الوقت.
- منع إعادة الإرسال بمفتاح حدث.
- تسليم قابل لإعادة المحاولة مع ترتيب غير مضمون.
- مستهلك مصمم للتكرار الآمن.
- لا يعد رد `200` تنفيذًا تجاريًا ناجحًا بالضرورة.
- توقف الوجهة المتكرر ينتج تنبيهًا وعزلًا دون فقد السجل.

## 30. الأسرار والمفاتيح

- لا تخزن الأسرار في الشفرة أو المستندات أو سجلات التدقيق.
- تحفظ في مخزن مخصص مع صلاحيات دقيقة.
- تدور دوريًا وعند الاشتباه.
- يفصل سر كل بيئة وتكامل.
- يظهر للمستخدم مرة واحدة عند الإنشاء، ويخزن مشتقه الآمن حيث يكفي.
- إبطال السر لا يحذف تاريخ استخدامه.

## 31. نقل البيانات والجهات الخارجية

قبل الإرسال إلى طرف خارجي:

- فحص الغرض والحد الأدنى.
- تقييم الطرف والموقع والضوابط.
- اتفاق معالجة وسرية.
- تحديد النقل عبر الحدود عند انطباقه.
- حق التدقيق والإخطار بالحوادث.
- خطة الإنهاء وإرجاع/إتلاف البيانات.

لا يتحول مزود الخدمة إلى مالك بيانات بسبب استضافتها.

## 32. حوكمة الذكاء الاصطناعي

كل استخدام للذكاء الاصطناعي في الاستخراج أو المطابقة أو التوصية أو المراجعة يسجل:

- الغرض والمالك.
- النموذج والإصدار.
- مصادر البيانات والحقوق.
- المدخلات والمخرجات المحفوظة.
- مقاييس الأداء والانحياز.
- حدود الاستخدام والثقة.
- التدخل البشري ومسار الاعتراض.
- المراقبة والتراجع.

لا يتخذ النظام قرار قبول عضوية أو جزاء أو استحقاق مالي جوهريًا آليًا دون قاعدة معتمدة ومراجعة بشرية مناسبة.

## 33. إدارة التغيير والإصدارات

- كل تغيير جوهري له طلب وأثر ومخاطر واختبار واعتماد.
- ترحيل البيانات قابل للعكس أو له خطة استعادة.
- تغييرات قواعد الأعمال تحفظ الإصدار الذي حكم كل قرار سابق.
- لا تعاد حسابات السمعة أو المطابقة تاريخيًا صامتًا.
- التغييرات الطارئة توثق وتراجع بعد التنفيذ.

- **GPSAI-BR-006:** يعاد تقييم الوصول في العملية الحساسة.
- **GPSAI-BR-007:** القراءة لا تمنح التنزيل أو المشاركة.
- **GPSAI-BR-008:** التعديل لا يمنح الاعتماد.
- **GPSAI-BR-009:** مدير النظام لا يمنح نفسه صلاحية أعمال.
- **GPSAI-BR-010:** لا يزال آخر مالك منظمة قبل تعيين بديل.

## 37. معايير القبول المفاهيمية

1. يمكن ربط كل قرار حساس بسياسة وإصدار وصاحب صلاحية.
2. يمنع المستخدم من اعتماد العملية التي نفذها عند وجوب الفصل.
3. لا يستطيع مدير النظام منح نفسه دور أعمال.
4. يستعيد المستخدم حسابه مع إبطال الجلسات السابقة.
5. تطبق الخصوصية فعليًا على الحقول والملفات العامة.
6. يمكن إثبات نص الموافقة وإصدارها وسحبها.
7. لا يؤدي تعطيل الحساب إلى حذف سجلات واجبة.
8. يحتفظ الحادث بخط زمني وأدلة وقرارات وإجراءات.
9. لا يستطيع المشغل تعديل أثر تدقيق فعله.
10. تمنع إعادة webhook أو طلب دفع من تكرار الأثر.
11. لا تمنح التكاملات أو النماذج وصولًا أوسع من غرضها.
12. يستطيع المتأثر الاعتراض على قرار آلي جوهري والحصول على مراجعة بشرية.
13. يمكن تتبع كل قاعدة أعمال إلى سياسة وضابط واختبار.
14. يمكن إعادة بناء «من فعل ماذا ولماذا وبأي صلاحية» لكل حدث جوهري.

## 38. بوابة اكتمال الحدود المفاهيمية

تعد الحدود المفاهيمية مكتملة عندما:

- يكون لكل مفهوم اسم واحد وتعريف ومالك مجال.
- لا يوجد كيانان يمثلان الحقيقة نفسها.
- تكون دورات الحياة وقواعد الانتقال محددة.
- ترتبط الحقوق والخصوصية والأمن بكل مجال.
- تكون نقاط التكامل والأحداث العابرة للمجالات معلنة.
- تكون القرارات المؤجلة معروفة وليست نواقص مخفية.
- توجد مصفوفة تتبع من المتطلبات إلى القواعد والكيانات والاختبارات.

الخطوة التالية بعد اعتماد هذه الحزمة هي **مراجعة الاتساق ومصفوفة التتبع وسجل القرارات المفاهيمية**، ثم تجميد خط أساس EIM المفاهيمي قبل تحديث النموذج المنطقي وقاموس البيانات وPostgreSQL DDL.
