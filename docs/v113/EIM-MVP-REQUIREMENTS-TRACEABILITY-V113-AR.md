# EIM-MVP-002 — سجل متطلبات MVP ومصفوفة التتبع التفصيلية

**الإصدار:** V113  
**المرجع:** EIM-MVP-001 + Conceptual Baseline 2.0 + Logical Model V70–V110  
**الحالة:** سجل متطلبات مضبوط وقابل للتحديث  
**قاعدة الحماية:** لا يحذف أي متطلب أو أثر سابق؛ التغيير يتم بإصدار وحالة وسبب.

## 1. الغرض

يحوّل هذا السجل نطاق MVP إلى متطلبات قابلة للإثبات. لكل متطلب رمز ثابت وأولوية ومسار وكيانات ومالك قرار ودليل تصميم وحالة وفجوة. وهو المرجع الذي يمنع:

- وجود شاشة بلا متطلب.
- وجود متطلب بلا مالك أو معيار قبول.
- وجود قاعدة أعمال لا يطبقها API أو لا يختبرها اختبار.
- إعلان الاكتمال اعتمادًا على نموذج بصري أو بيانات تجريبية فقط.

## 2. سلم الأولوية والحالة

| الرمز | التعريف |
|---|---|
| P0 | حرج؛ غيابه يمنع MVP أو يسبب خطر هوية/مال/خصوصية/عقد |
| P1 | أساسي؛ يلزم لرحلة مكتملة وقابلة للاستخدام |
| P2 | داعم؛ يمكن تقييد نطاقه في الإطلاق الأول دون كسر النواة |
| C | مكتمل مفاهيميًا |
| D | ممثل في التصميم التنفيذي/DDL/API/الشاشة/الاختبار |
| L | متصل بخدمة حية ومصدر حقيقة إنتاجي |
| A | مقبول عبر UAT والأمن والأداء والتدقيق |

الحالة الحالية تسجل `C+D` عندما يوجد الدليل المرجعي. لا تسجل `L` أو `A` قبل إثبات بيئة حية.

## 13. معايير قبول سجل المتطلبات

1. لكل متطلب رمز ثابت لا يعاد استخدامه.
2. كل P0 مرتبط بمسار وكيان ومالك وقاعدة ودليل وفجوة.
3. لا توجد حالة L أو A بلا مرجع بيئة ونتيجة اختبار وتاريخ.
4. أي تغيير في المتطلب يحفظ الإصدار والسبب والأثر.
5. لا يحذف متطلب ملغى؛ ينقل إلى `Retired` مع بديله.
6. تستخدم هذه الرموز في قصص المستخدم وOpenAPI والاختبارات وتقارير UAT.
